# HairGuard

[English version](README.md)

Программа ловит момент, когда вы начинаете накручивать волосы, и прерывает
вас: на весь экран появляется сообщение и звучит сигнал, пока рука не ушла.
Нужна тем, кто борется с трихотилломанией, где рука обычно поднимается к
голове сама, без участия сознания.

Работает в трее, смотрит в веб-камеру, всё считает на вашей машине. Видео
никуда не отправляется и не сохраняется, пока вы сами не включите запись.

Это не лечение. Это способ заметить момент.

## Запуск

Скачайте архив, распакуйте, запустите. Python и установка не нужны: внутри
уже лежат все модели.

| Система | Как запустить |
|---------|---------------|
| Windows | двойной щелчок по `HairGuard.exe` |
| macOS | перетащить `HairGuard.app` в Applications, [сначала прочитайте про Gatekeeper](#macos) |
| Linux | один раз запустить `./install-desktop-entry.sh`, дальше из меню программ |

Появится значок в трее (на macOS в строке меню). Больше ничего делать не
надо.

Чтобы запускалось вместе с системой:

```
hairguard-cli autostart on
```

`hairguard-cli` лежит в той же папке. Для обычной работы он не нужен,
только когда что-то пошло не так.

## Что в трее

| Пункт | Что делает |
|-------|------------|
| Пауза | выключает тревоги, сама включается обратно через 15 минут |
| Статистика | сколько эпизодов было сегодня |
| Детектор | показывает, какой детектор сейчас решает |
| Сбор данных | запись клипов для обучения своей модели |
| Диагностика | окно с тем, что детектор видит прямо сейчас |
| Открыть журнал | `~/.hairguard/hairguard.log` |

## Если не работает

Консоли у приложения нет, поэтому оно пишет журнал. Три шага по порядку.

**Откройте диагностику из трея.** Там видно скелет руки, зону волос и все
числа, по которым принимается решение, кадр за кадром. Обычно вопрос один:
что оно вообще сейчас видит. Это ответ на него.

Своей камеры у окна нет, кадры ему присылает само приложение. Так сделано
намеренно: камеру держит работающее приложение, а в Windows повторный захват
занятой камеры не выдаёт ошибку, он молча отдаёт чёрные кадры.

**Спросите, что у него есть.**

```
hairguard-cli doctor
```

Скажет, какой детектор будет работать и почему, на месте ли модели, запущен
ли уже экземпляр. Камеру не трогает, можно запускать при работающем
приложении.

**Посмотрите журнал.**

```
hairguard-cli log --tail 50
```

Если приложение падает до появления значка в трее, трассировка будет там.

## Настройка

Файл `~/.hairguard/config.yaml` создаётся при первом запуске.

```yaml
camera: auto                     # индекс камеры или "auto"
camera_width: 1280
camera_height: 720

detection:
  fps: 10
  trigger_delay_sec: 0.8         # сколько держится обнаружение до тревоги
  dismiss_delay_sec: 2.5         # сколько тревога висит после ухода руки
  model:
    enabled: true                # false вернёт старое геометрическое правило
    min_frames: 3                # сколько кадров собрать, прежде чем спросить модель
    trigger_delay_sec: 0.3

alert:
  opacity: 0.7
  sound: true                    # повторяется, пока рука у головы
```

Неправильные значения заменяются на стандартные, о чём пишется при запуске.

## Как это работает

На каждом кадре три модели MediaPipe дают позу, кисти и сетку лица. Дальше
два вопроса.

Первый дешёвый: кончики пальцев находятся выше линии роста волос? Если нет,
дальше никто не считает.

Второй трудный: это накручивание пряди или рука просто лежит на голове? На
него отвечает небольшая нейросеть, обученная на размеченных примерах. Она
смотрит на движение кисти за последние два секунды, приведённое к системе
отсчёта головы, поэтому расстояние до камеры и наклон головы ей не мешают.

Замеры на днях съёмки, которых модель при обучении не видела:

| | Ловит | Ложные тревоги | Время до тревоги |
|---|---|---|---|
| Геометрическое правило | 37.7% | 10.3% | 1.20 с |
| Обученная модель | 80.7% | 6.9% | 0.72 с |

Модель лежит в [`hairguard/models/`](hairguard/models) и работает сразу
после установки. Внутри только веса и порог, никакого видео и никаких личных
данных. Если модель не загрузилась, приложение работает на геометрическом
правиле и прямо об этом пишет при запуске, чтобы откат нельзя было принять
за плохую работу модели.

Важная оговорка. Числа выше получены на данных одного человека: его волосы,
его камера, его привычки. Трихотилломания у разных людей выглядит
по-разному: голова, брови, ресницы, одна рука или обе. Считайте встроенную
модель отправной точкой, а не потолком, и обучите свою.

## Обучить свою модель

**1. Собрать клипы.** Запись выключена, пока вы её не включите.

```
python -m hairguard collect on
```

Клипы по две секунды пишутся, когда пальцы оказались в зоне волос, без
всякой оценки того, что рука делала. Оценивать на этом шаге значило бы
научить новую модель тому, во что уже верит старая. Около 200 КБ на клип.

**2. Разметить.** Интерфейс в браузере крутит клип петлёй, метки ставятся с
клавиатуры: накручиваю, просто держу, чешу, предмет в руке, не разобрать.

```
python -m hairlab label
python -m hairlab stats
```

Рабочий минимум, несколько сотен клипов на каждый класс. Это примерно пара
недель обычного пользования.

**3. Обучить.**

```
python -m hairlab train --cv      # честная оценка
python -m hairlab train           # итоговая модель
```

Две вещи, в которых легко ошибиться и получить прекрасные числа, не значащие
ничего.

Данные делятся **по целым дням съёмки**, никогда не случайно. Клипы, снятые
с разницей в секунды, почти одинаковы, и при случайном делении вы будете
обучаться и проверяться на одном и том же эпизоде.

Главная метрика, **доля ложных тревог отдельно по каждому типу**: на лежащей
руке, на чесании, на предмете в руке. Не общая точность. Точность усредняет
ровно ту ошибку, из-за которой программу удалят: она дёргает вас, когда вы
просто облокотились на руку.

Порог тоже выбирается не по максимуму F1. F1 считает пропуск и ложную
тревогу одинаково вредными, а они совсем не равны, когда вам закрывают
экран. Берётся самый низкий порог, при котором ложные на лежащей руке
остаются ниже 5%.

## Приватность

Всё считается локально, никуда ничего не уходит. Скачанное приложение в сеть
не ходит вообще: модели лежат внутри.

Видео не пишется, пока вы не включите сбор. Клипы, метки, история эпизодов и
обученная модель лежат в `~/.hairguard/` и в репозиторий не попадают.

Окно диагностики, это дочерний процесс, который получает кадры через канал,
а не через сокет. Никакой порт не слушается, и подключиться к вашему видео
ничто другое на машине не может.

## Из исходников

Нужен Python 3.11 или новее.

```bash
git clone https://github.com/CRaFT4ik/hairguard
cd hairguard
pip install -e .

# если собираетесь обучать свою модель
pip install -e ".[lab]" -e ".[train]"

python -m hairguard start
python -m hairguard cameras        # список камер, если автовыбор ошибся
python -m hairguard stats
python -m hairguard doctor
python -m hairguard stop
```

## Платформы

| Платформа | Состояние |
|-----------|-----------|
| Windows 10/11 | Полная поддержка, сборка проверена |
| Linux (X11) | Работает из исходников, сборка написана но не проверена |
| Linux (Wayland) | Нужен `gtk-layer-shell`: `pip install hairguard[wayland]` |
| macOS | Работает из исходников, `.app` не проверен |

### macOS

Всё в этом разделе выведено из документации, а не проверено на живой машине:
сборки делались на Windows.

**Gatekeeper откажется запускать.** Приложение не подписано, и macOS скажет,
что оно повреждено и его надо удалить. Оно не повреждено, так macOS сообщает
про карантин. Снять метку:

```bash
xattr -dr com.apple.quarantine /Applications/HairGuard.app
```

Иногда помогает правый клик и пункт "Открыть". Нормальное решение это платный
Apple Developer и подпись, которой у проекта нет.

**Собирайте на том же Маке, где будете запускать.** Сборка под Apple Silicon
не пойдёт на Intel и наоборот, универсальной сборки нет.

**Разрешите доступ к камере** при первом запуске. Если отказать, приложение
ничего не увидит, а в журнале будет видно, что камера не открывается.
Поправить: Системные настройки, Конфиденциальность и безопасность, Камера.

Значка в Dock не будет, программа живёт только в строке меню. Разрешения на
запись экрана и универсальный доступ не нужны.

### Linux

Тоже не проверялось. В папке со сборкой лежит `install-desktop-entry.sh`,
он добавляет программу в меню, root не нужен.

Под Wayland полноэкранному окну нужен `gtk-layer-shell`, которого в сборке
нет, поэтому под Wayland ставьте из исходников. И glibc в сборку не входит:
собранное на свежем дистрибутиве не запустится на старом, так что собирайте
на самой старой системе, которую хотите поддерживать.

## Сборка

```bash
pip install -e ".[package]"
python bundle/build.py
```

Результат появится в `dist/` вместе с zip-архивом. Минута работы, примерно
300 МБ распакованными и 137 МБ в архиве, из которых 118 МБ это OpenCV.

Сборка отказывается работать, а не выдаёт тихо испорченный результат. Она не
начнётся без обученной модели, потому что приложение без неё запускается и
выглядит рабочим, ловя вдвое меньше. Она не закончится, если внутрь попал
обучающий стек: один torch весит 2.8 ГБ, а для запуска готовой модели он не
нужен. В конце она запускает собранный бинарник с пустым домашним каталогом,
чтобы он не нашёл модель разработчика, и спрашивает, что он выберет.
