# HairGuard

🇬🇧 [English version](README.md)

Настольный инструмент для тех, кто работает над тем, чтобы прервать
трихотилломанию — навязчивое выдёргивание волос.

Поведение обычно автоматическое: начинается незаметно и часто успевает
закончиться раньше, чем человек его осознал. HairGuard смотрит в веб-камеру в
фоне, распознаёт накручивание пряди в момент начала и прерывает его
полноэкранным сообщением и повторяющимся сигналом, который смолкает, как
только рука ушла.

Всё считается на вашей машине. Видео никуда не уходит и нигде не сохраняется,
пока вы сами не включите запись.

Это не лечение. Это прерывание, которое имеет смысл рядом с лечением.

---

## Как работает обнаружение

На каждом кадре работают три модели MediaPipe — поза, кисти и сетка лица, —
давая положение головы, линии роста волос и все 21 точку каждой кисти.

Сначала задаётся дешёвый геометрический вопрос: находятся ли кончики пальцев
в зоне волос над линией роста? И только потом трудный: это накручивание пряди
или просто рука лежит на голове?

На второй отвечает небольшая временная свёрточная сеть, обученная на
размеченных примерах. Она читает скользящее окно геометрии кисти и головы,
нормализованной в систему отсчёта головы — поэтому неважно, как далеко вы
сидите и как наклонили голову, — и возвращает вероятность. Дальше машина
состояний требует, чтобы сигнал продержался, и удерживает тревогу ещё
немного после ухода руки.

Измерено на днях съёмки, которых модель при обучении не видела:

| | ловит | ложные на лежащей руке | время до тревоги |
|---|---|---|---|
| Геометрическое правило | 37.7% | 10.3% | 1.20 с |
| Обученная модель | **80.7%** | **6.9%** | **0.72 с** |

Обученная модель поставляется вместе с пакетом, в
[`hairguard/models/`](hairguard/models), поэтому обнаружение работает сразу
после установки. В ней только веса сети и порог — ни видео, ни изображений,
ни каких-либо личных данных. Если вы обучите свою, она получит приоритет
автоматически.

Если модель загрузить не удалось, приложение работает на геометрическом
правиле и прямо сообщает об этом при запуске — чтобы откат нельзя было
принять за плохую работу модели.

### Встроенная модель принадлежит тому, кто её обучал

Эти числа получены на данных одного человека: его волосы, его камера, его
привычки. Выдёргивание волос у разных людей проявляется очень по-разному —
голова, брови, ресницы, одна рука или обе, накручивание или выщипывание.
Считайте встроенную модель рабочей отправной точкой, а не потолком.

Обучение на собственных данных — предполагаемый путь, и всё необходимое для
него включено.

## Установка

### Приложение

Скачайте архив для своей системы, распакуйте и запустите `HairGuard`. Он
появится в системном трее (в строке меню на macOS) и останется там. Ни
Python, ни терминала, ни чего-либо ещё ставить не нужно: обученная модель и
три модели MediaPipe лежат внутри, так что распознавание работает с первого
запуска и без интернета.

| | что внутри | как запустить |
|---|---|---|
| **Windows** | папка с `HairGuard.exe` | двойной щелчок по `HairGuard.exe` |
| **macOS** | `HairGuard.app` | перетащить в Applications — [сначала прочтите это](#macos) |
| **Linux** | папка с `HairGuard` | один раз `./install-desktop-entry.sh`, дальше из меню |

Запускать вместе с системой:

```
hairguard-cli autostart on      # Windows: hairguard-cli.exe autostart on
```

`hairguard-cli` лежит в той же папке — это вся командная строка. Для
обычной работы он не нужен; он нужен, когда что-то пошло не так.

### Из исходников

Требуется Python 3.11+.

```bash
git clone https://github.com/CRaFT4ik/hairguard
cd hairguard
pip install -e .

# Чтобы собирать данные и обучать свою модель
pip install -e ".[lab]" -e ".[train]"
```

## Быстрый старт

```bash
python -m hairguard start          # обнаружение, со значком в трее
python -m hairguard cameras        # список камер, если автовыбор ошибся
python -m hairguard stats          # эпизоды за сегодня против вчера
python -m hairguard doctor         # что установлено и какой детектор будет работать
python -m hairguard stop
```

При запуске приложение печатает, какую камеру выбрало и какой детектор
работает. Всё, что оно печатает, попадает и в `~/.hairguard/hairguard.log`.

### Меню в трее

| пункт | |
|---|---|
| Пауза | останавливает обнаружение, само возобновляется через 15 минут |
| Статистика | эпизоды за сегодня |
| Детектор | какой из двух детекторов решает прямо сейчас |
| Сбор данных | начать или остановить запись клипов для обучения |
| **Диагностика** | окно с тем, что видит детектор |
| **Открыть журнал** | открывает `~/.hairguard/hairguard.log` |

## Если что-то идёт не так

У приложения нет консоли, поэтому оно пишет журнал. Три вещи по порядку.

**Откройте окно диагностики из трея.** Оно рисует скелет руки, зону волос и
все значения, по которым детектор принимает решение, — включая оценку модели
против её порога, кадр за кадром. «Что оно сейчас видит» — обычно
единственный полезный вопрос, и это ответ на него.

Своей камеры у окна нет. Камеру держит работающее приложение, а в Windows
повторное открытие занятой камеры не даёт ошибки — оно молча отдаёт чёрные
кадры. Поэтому окно — отдельный процесс, которому кадры и состояние
присылает сам цикл обнаружения: оно показывает ровно то, по чему детектор
принял решение, и не может ни подвесить, ни уронить тревогу.

(Команда `hairguard debug` устроена наоборот: открывает свою камеру и
запускает свою копию конвейера — это правильно, когда приложение **не**
работает. Пока оно работает, команда отказывается запускаться и объясняет,
почему.)

**Спросите, что у него есть.**

```
hairguard-cli doctor
```

Какой детектор будет решать и почему, доступен ли извлекатель признаков, с
которым сверяется модель, есть ли `onnxruntime`, откуда взялась каждая
модель MediaPipe, запущен ли уже экземпляр. Камеру не открывает — безопасно
запускать при работающем приложении.

**Прочитайте журнал.**

```
hairguard-cli log --tail 50
```

`~/.hairguard/hairguard.log`, с отметками времени, с ротацией на половине
мегабайта и одним предыдущим файлом. Если приложение умирает до появления
значка в трее, трассировка будет там, а на экране появится окно с
сообщением.

## Настройка

`~/.hairguard/config.yaml`, создаётся при первом запуске.

```yaml
camera: auto                     # индекс или "auto" для поиска рабочей
camera_width: 1280               # детализация кисти ограничивает качество модели
camera_height: 720

detection:
  fps: 10
  trigger_delay_sec: 0.8         # сколько держится обнаружение до тревоги
  dismiss_delay_sec: 2.5         # сколько тревога висит после ухода руки
  model:
    enabled: true                # false — откат на геометрическое правило
    min_frames: 3                # кадров доказательств, прежде чем спрашивать модель
    trigger_delay_sec: 0.3

alert:
  opacity: 0.7
  sound: true                    # повторяется, пока рука у головы
```

Некорректные значения выводятся при запуске и заменяются значениями по
умолчанию.

## Как обучить модель под себя

Пакет `hairlab` закрывает весь путь от веб-камеры до работающей модели.

**1. Сбор.** Запись выключена, пока вы её не включите, и состояние громко
объявляется при каждом запуске.

```bash
python -m hairguard collect on
```

Клипы примерно по две секунды сохраняются, когда кончики пальцев в зоне
волос — без всякой оценки того, что делала рука: оценивать здесь значило бы
научить модель тому, во что уже верит существующий детектор. Каждый клип —
квадратная вырезка, следующая за кистью, плюс координаты точек. Около 200 КБ
на клип.

**2. Разметка.** Интерфейс в браузере проигрывает клип петлёй для разметки с
клавиатуры: накручиваю, просто держу, чешу, предмет в руке, не разобрать.

```bash
python -m hairlab label
python -m hairlab stats     # прогресс и пригодность данных
```

Рабочий минимум — несколько сотен клипов на класс. Ожидайте пару недель
обычного пользования, чтобы их набрать.

**3. Обучение.**

```bash
python -m hairlab train --cv      # честная оценка, кросс-валидация по дням
python -m hairlab train           # итоговая модель в ~/.hairguard/trained
```

Две вещи об оценке стоит знать, потому что ошибка в них даёт числа, которые
выглядят прекрасно и не значат ничего.

Разбиение идёт **по целым дням съёмки**, никогда не случайно. Клипы, снятые с
разницей в секунды, почти одинаковы, так что случайное разбиение обучает и
проверяет на одном и том же эпизоде.

Главная метрика — **доля ложных срабатываний по типам отрицательных примеров**:
отдельно на лежащей руке, на чесании, на предмете в руке. Не общая точность.
Точность усредняет ровно ту ошибку, которая важна: инструмент, который
прерывает вас, когда вы просто облокотились на руку, выключат, какая бы
точность у него ни была.

Рабочий порог тоже выбирается не по максимуму F1. F1 оценивает пропуск и
ложную тревогу одинаково, а для того, что прерывает вас полноэкранным
сообщением, они совершенно не равны. Берётся самый низкий порог, удерживающий
ложные срабатывания на лежащей руке ниже 5%.

## Приватность

- Все вычисления локальные. Ничего не выгружается. Скачанное приложение в
  сеть не ходит вовсе — модели MediaPipe лежат внутри; установка из
  исходников скачивает их один раз при первом запуске.
- Окно диагностики — дочерний процесс, который общается с приложением через
  канал, а не через сокет. Ни один порт не слушается, и никакая другая
  программа на машине не может подключиться к видео.
- Видео не записывается, пока вы не включите сбор.
- Собранные клипы, метки, история эпизодов и обученная модель лежат в
  `~/.hairguard/` и никогда не попадают в репозиторий.
- Статистика эпизодов — счётчики и метки времени в локальном файле SQLite.

## Поддержка платформ

| Платформа | Состояние |
|-----------|-----------|
| Windows 10/11 | Полная поддержка. Сборка собрана и проверена здесь. |
| Linux (X11) | Полная поддержка из исходников. Конфигурация сборки написана, но не проверена. |
| Linux (Wayland) | Оверлей через `gtk-layer-shell` — `pip install hairguard[wayland]` |
| macOS | Автозапуск и статистика поддержаны; оверлей проверен меньше. `.app` не проверен — см. ниже. |

### macOS

Всё в этом разделе выведено из документации, а не увидено: сборки делались
на Windows, и ни один шаг для macOS не выполнялся. Первое из перечисленного
встретится почти наверняка.

**Gatekeeper откажется запускать неподписанное приложение.** `.app` не
подписан и не нотаризован, поэтому скачанная браузером копия помечается
карантином, и macOS скажет, что приложение повреждено и его надо перенести в
корзину. Оно не повреждено — так macOS сообщает «не подписано и в
карантине». Снять метку:

```bash
xattr -dr com.apple.quarantine /Applications/HairGuard.app
```

На части версий помогает правый клик → «Открыть». Настоящее решение —
платный Apple Developer, `codesign --deep --options runtime` и `notarytool`;
у проекта этого нет.

**Собирайте на том Маке, на котором будете запускать.** `.app`, собранный на
Apple Silicon, не запустится на Intel, и наоборот: колёса OpenCV и MediaPipe
содержат бинарники под конкретную архитектуру, а упаковщик кладёт ту, что
нашёл. Универсальной сборки здесь нет.

**На запрос камеры надо ответить.** В сборке объявлен
`NSCameraUsageDescription`, без которого macOS убивает процесс в момент
обращения к камере — молча, без всякого запроса. С ним при первом запуске
появляется запрос. Если отказать (или если запрос не появился), приложение
ничего не увидит: Системные настройки → Конфиденциальность и безопасность →
Камера. В журнале будет видно, что камера не открывается.

**Иконки в Dock не будет.** Выставлен `LSUIElement`, так что приложение
живёт только в строке меню — это правильно для программы без окна, но и
закрывать её нужно из строки меню, а не через ⌘Q.

Разрешения «Универсальный доступ» и «Запись экрана» **не** нужны: оверлей —
обычное окно поверх других, и ничего не читает ни с экрана, ни с клавиатуры.

### Linux

Тоже не проверено — написано на Windows и не запускалось. Сборка — это
папка; лежащий в ней `install-desktop-entry.sh` создаёт `.desktop`-запись в
`~/.local/share/applications` с путём туда, куда вы распаковали, и именно
это добавляет приложение в меню. Права root не нужны.

Два ожидаемых момента. Полноэкранный оверлей использует подсказки окон X11,
а под Wayland ему нужен `gtk-layer-shell`, которого в сборке нет — под
Wayland ставьте из исходников с `pip install hairguard[wayland]`. И glibc в
сборку не входит: папка, собранная на свежем дистрибутиве, не запустится на
старом, так что собирайте на самой старой системе, которую хотите
поддерживать.

## Сборка приложения

```bash
pip install -e ".[package]"
python bundle/build.py
```

Результат появится в `dist/`, рядом — zip. Занимает около минуты и даёт
примерно 300 МБ распакованными и 137 МБ в архиве, из которых OpenCV — 118 МБ,
onnxruntime — 32 МБ.

Запускать надо на той платформе, под которую собираете; кросс-сборки нет.
Всё, что решает, что попадёт внутрь, лежит в
[`bundle/buildconf.py`](bundle/buildconf.py).

Сборка отказывается работать, а не выдаёт что-то незаметно неправильное. Она
не начнётся без обученной модели: приложение, откатившееся на пороговое
правило, запускается нормально и выглядит рабочим, ловя вдвое меньше. Она не
закончится, если внутрь попало что-то из обучающего стека — один torch
весит 2.8 ГБ, а приложению он не нужен, чтобы запускать то, что torch сделал.
После сборки она запускает полученный бинарник с домашним каталогом,
направленным в пустую папку, — чтобы он не нашёл модель разработчика — и
заставляет его сказать, какой детектор он выберет и всё ли на месте.
